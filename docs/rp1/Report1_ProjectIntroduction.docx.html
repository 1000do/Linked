2. Product Background

The rapid growth of online learning and digital skills training has created a strong demand for flexible platforms where instructors can easily publish courses and users can conveniently access high-quality educational content. Currently, many individuals who possess valuable knowledge and teaching ability face difficulties in distributing their courses effectively. They often rely on social media, personal websites, or third-party platforms that are either technically complex, costly, or provide limited control over content, users, and revenue.

At the same time, users increasingly prefer online courses because of their convenience, accessibility, and diversity of topics. However, they must search across multiple websites and informal channels to find suitable courses, evaluate credibility, make payments, and store learning materials. This fragmented process causes inconvenience, lack of trust, and inconsistent learning experiences.

The idea of the Online Course Marketplace System (OCMS) was raised to address these issues by creating a centralized platform that connects course creators and users. OCMS aims to provide an integrated environment where instructors can register, upload and manage their courses (including video lectures and learning materials), while users can browse, purchase, and study courses directly on the system. The primary customers of this product include independent instructors, training centers, and individuals or organizations seeking to commercialize educational content, as well as students, self-learners, and working professionals who want to improve their knowledge and skills through online courses.

2.1 C# (ASP.NET Core (.NET 8))

Figure 1. Logo of C# ASP.NET Core (.NET 8)

a. Introduction to ASP.NET Core (.NET 8) 

ASP.NET Core is a high-performance, open-source, and cross-platform framework developed by Microsoft for building modern, cloud-enabled, and Internet-connected apps. In .NET 8, it serves as the unified platform for building Web APIs, Microservices, and full-stack web UIs (Blazor), leveraging the latest C# features and a highly optimized runtime. It plays a role similar to Spring Boot in the Java ecosystem or Express.js in the Node.js environment.

b. Advantages of ASP.NET Core (.NET 8)

  • .NET 8 is one of the fastest web frameworks available, featuring significant JIT compiler and runtime optimizations.
  • Develop and deploy applications on Windows, Linux, and macOS, including seamless support for Docker and Kubernetes.
  • Provides a single consistent model (MVC/Web API) for building diverse application types.
  • Enhanced support for Ahead-of-Time compilation, resulting in faster startup times and smaller memory footprints.
  • Backed by Visual Studio and a robust NuGet ecosystem, offering advanced debugging, profiling, and testing tools.

c. Disadvantages of ASP.NET Core (.NET 8)

  • The framework is vast with many built-in features (Dependency Injection, Middleware, Filters), which can be overwhelming for beginners.
  • The frequent release cycle (major updates every year) requires teams to stay updated and migrate codebases regularly.
  • Some built-in magic and deep abstractions can make it difficult to troubleshoot low-level issues when things go wrong.
  • While greatly improved, it can still consume more memory than extremely lightweight frameworks (like Go or Rust) in certain micro-service scenarios.

2.2 Swagger

Figure 2. Logo of Swagger

a. Introduction to Swagger

Swagger (OpenAPI) is a toolset for designing, documenting, and testing RESTful APIs. In .NET projects, Swagger is commonly integrated into ASP.NET Core to automatically generate interactive API documentation.

Swagger provides a web-based UI that allows developers and testers to explore API endpoints, send requests, and view responses without external tools like Postman.

b. Advantages of Swagger

  • Automatic API Documentation: Reduces manual documentation effort.
  • Interactive API Testing: APIs can be tested directly from the browser.
  • Improves Team Collaboration: Clear API contracts between frontend and backend teams.
  • Standardized API Specification: Follows OpenAPI standards.
  • Easy Integration with ASP.NET Core: Minimal configuration required.

c. Disadvantages of Swagger

  • Limited Customization: Advanced UI customization can be complex.
  • Security Risks if Exposed in Production: Should be disabled or protected in live environments.
  • Not a Replacement for Full API Testing Tools: Less powerful than Postman for advanced testing.

2.3 Docker

Figure 3. Logo of Docker

a. Introduction to Docker

Docker is a containerization platform that allows applications to be packaged with all their dependencies into lightweight containers. It enables consistent deployment across different environments such as development, testing, and production.

In .NET systems, Docker is commonly used to containerize ASP.NET Core APIs, databases, and supporting services, similar to how Docker is used in Node.js-based microservices architectures.

b. Advantages of Docker

  • Environment Consistency: Eliminates “it works on my machine” issues.
  • Faster Deployment: Applications start quickly with minimal setup.
  • Scalability: Supports microservices and horizontal scaling.
  • Easy Integration with CI/CD Pipelines: Ideal for DevOps workflows.
  • Cross-Platform Support: Runs consistently across different operating systems.

c. Disadvantages of Docker

  • Learning Curve: Requires understanding containers, images, and networking.
  • Resource Overhead: Containers still consume system resources.
  • Debugging Complexity: Harder than debugging local applications.
  • Security Configuration Required: Misconfigured containers may expose vulnerabilities.

2.4 SignalR (Real-Time Communication)

Figure 4. Logo of SignalR (Real-Time Communication)

a. Introduction to SignalR

SignalR is a real-time communication library for ASP.NET Core that enables server-to-client push functionality. It serves a similar purpose to Socket.IO in Node.js-based systems.

SignalR allows applications to support real-time features such as live notifications, chat systems, and real-time dashboards using WebSockets and fallback transports.

b. Advantages of SignalR

  • Real-Time Updates: Enables instant data synchronization.
  • Automatic Transport Fallback: Works even when WebSockets are unavailable.
  • Strong Integration with ASP.NET Core: Native support and easy configuration.
  • Scalable Architecture: Works with Redis or cloud services for scaling.
  • Secure Communication: Supports authentication and authorization.

c. Disadvantages of SignalR

  • Higher Resource Usage: Persistent connections increase server load.
  • Scaling Complexity: Requires additional infrastructure for large systems.
  • Less Popular Than Socket.IO: Smaller community and fewer tutorials.

2.5 JSON Web Token (JWT) in .NET

Figure 5. Logo of JSON Web Token (JWT) in .NET

a. Introduction to JWT in .NET

JWT is widely used in ASP.NET Core for implementing stateless authentication and authorization. It functions similarly to Jsonwebtoken in Node.js, enabling secure communication between client and server without maintaining session state.

b. Advantages of JWT in .NET

  • Stateless Authentication: Improves scalability.
  • Secure Token-Based Access Control.
  • Easy Integration with ASP.NET Core Middleware.
  • Cross-Platform Compatibility: Works with web and mobile clients.

c. Disadvantages of JWT in .NET

  • Token Revocation Complexity.
  • Security Risks if Secret Keys Are Leaked.
  • Requires Careful Expiration Management.

2.6 HTML

Figure 6. Logo of HTML

a. Introduction to HTML

HTML (HyperText Markup Language) is the standard markup language used to create and structure content on the web. It defines the layout of a web page by using elements such as headings, paragraphs, images, links, forms, and tables.

In ASP.NET Core applications, HTML is commonly used within Razor Pages or MVC Views to display dynamic data returned from the backend to users.

b. Advantages of HTML

  • Fundamental technology for all web applications.
  • Simple syntax and easy to learn.
  • Supported by all modern web browsers.
  • Integrates seamlessly with CSS and JavaScript.
  • Works well with server-side rendering frameworks such as ASP.NET Core MVC.

c. Disadvantages of HTML

  • Limited to defining structure and content only.
  • Does not support logic or data processing.
  • Static by itself without CSS and JavaScript.
  • Large projects can become difficult to manage without proper organization.

2.7 CSS

Figure 7. Logo of CSS

a. Introduction to CSS

CSS (Cascading Style Sheets) is a style sheet language used to control the presentation and layout of web pages. It defines visual aspects such as colors, fonts, spacing, positioning, animations, and responsive design.

In ASP.NET Core systems, CSS is used to enhance the appearance of HTML content and ensure consistent design across different pages and devices.

b. Advantages of CSS

  • Separates presentation from content.
  • Enables responsive and mobile-friendly design.
  • Improves user experience with visual consistency.
  • Reduces code duplication by reusing styles.
  • Supported by all modern browsers.

c. Disadvantages of CSS

  • Can become complex in large-scale applications.
  • Style conflicts may occur if not well structured.
  • Different browser behaviors may require additional handling.
  • Advanced layouts and animations have a learning curve.

2.8 Tailwind CSS

Figure 8. Logo of Tailwind CSS

a. Introduction to Tailwind CSS

Tailwind CSS is a utility-first CSS framework that allows developers to build custom user interfaces by applying predefined utility classes directly in HTML.
Unlike component-based frameworks such as Bootstrap, Tailwind CSS emphasizes flexibility and fine-grained control over styling.

In ASP.NET Core and modern web applications, Tailwind CSS helps speed up UI development while maintaining consistency and scalability.

b. Advantages of Tailwind CSS

  • Rapid UI development.
  • Highly customizable design system.
  • Reduces the need to write custom CSS.
  • Optimized and lightweight in production builds.
  • Integrates well with Razor Pages, React, and Vue.

c. Disadvantages of Tailwind CSS

  • HTML files can become verbose with many classes.
  • Steeper learning curve for beginners.
  • Requires a build process (PostCSS, npm).
  • Not ideal for very small or simple projects.

2.9 AJAX

Figure 9. Logo of AJAX

a. Introduction to AJAX

AJAX is a web development technique that enables asynchronous communication between the client and server without reloading the entire web page.
In ASP.NET Core applications, AJAX is commonly used to call RESTful APIs, submit forms, implement search features, pagination, and dynamically update user interfaces.

AJAX can be implemented using vanilla JavaScript, jQuery, or the Fetch API.

b. Advantages of AJAX

  • Improves user experience with smooth interactions.
  • Reduces server load and network traffic.
  • Faster response times for dynamic content updates.
  • Easily integrates with RESTful APIs.
  • Suitable for modern and interactive web applications.

c. Disadvantages of AJAX

  • More difficult to debug than traditional requests.
  • Depends heavily on JavaScript execution.
  • State management can become complex in large systems.
  • Potential security risks if APIs are not properly protected.

2.10 Cloudinary

Figure 10. Logo of Cloudinary

a. Introduction to Cloudinary

Cloudinary is a cloud-based media management platform used to store, optimize, and deliver images and videos for web and mobile applications. In modern development, Cloudinary acts as a SaaS solution that automates media workflows, eliminating the need for manual image processing or maintaining local storage servers. It plays a role similar to Amazon S3 combined with image processing services like Imgix or Cloudimage.

b. Advantages of Cloudinary

  • Automatically adjusts format and quality to reduce file size without losing visual clarity.
  • Resizes, crops, and applies filters instantly by simply modifying URL parameters.
  • Delivers media via global Content Delivery Networks for high-speed performance worldwide.
  • Provides comprehensive libraries for various environments including .NET, Node.js, Python, and React.
  • Offers a powerful dashboard for organizing, searching, and managing media assets.

c. Disadvantages of Cloudinary

  • Pricing can scale quickly and become expensive once free tier limits (bandwidth/storage) are exceeded.
  • Reliability depends entirely on Cloudinary’s uptime and service availability.
  • Mastering the extensive syntax for URL-based transformations requires initial time and effort.
  • Migrating a large volume of assets and updating hardcoded URLs to another provider can be difficult.

2.11 Redis

Figure 11. Logo of Redis

a. Introduction to Redis

Redis (Remote Dictionary Server) is an open-source, in-memory data structure store used as a database, cache, and message broker. Unlike traditional databases that store data on disk, Redis keeps data in RAM for lightning-fast access.

In ASP.NET Core applications, Redis is widely used to implement distributed caching, manage session state across multiple servers, and handle real-time data messaging via its Pub/Sub capabilities.

Redis supports various data structures such as strings, hashes, lists, sets, and sorted sets with range queries.

b. Advantages of Redis

  • Exceptionally high performance.
  • Flexible data structures.
  • Data persistence.
  • Scalability and High Availability.
  • Rich feature set.

c. Disadvantages of Redis

  • Memory-intensive.
  • Complexity in large-scale setups.
  • No relational mapping.
  • Risk of data loss.

2.12 PostgreSQL

Figure 12. Logo of PostgreSQL

a. Introduction to PostgreSQL

PostgreSQL (Postgres) is an advanced, open-source object-relational database management system (ORDBMS) known for its reliability, feature robustness, and performance. In application development, it is used as the primary data store to handle structured data, complex queries, and ensure data integrity through ACID compliance. Postgres plays a role similar to MySQL, Microsoft SQL Server, or Oracle Database in backend architecture.

b. Advantages of PostgreSQL

  • Supports custom data types, operators, and functions (e.g., PostGIS for geographic data).
  • Strictly adheres to SQL standards and supports advanced features like Window Functions and Common Table Expressions (CTEs).
  • Offers robust ACID compliance and sophisticated locking mechanisms to prevent data corruption.
  • Excellent support for NoSQL-style JSONB storage, allowing for high-performance semi-structured data queries.
  • Free to use with a massive ecosystem of plugins and active community support.

c. Disadvantages of Redis

  • Can be slower than MySQL for simple, read-heavy operations due to its complex feature set.
  • Typically consumes more memory and CPU per connection compared to lighter databases like MariaDB.
  • The vast array of advanced features and configuration options creates a steeper learning curve for beginners.
  • Requires regular "Vacuuming" to reclaim storage space from deleted or updated rows, which can impact performance if mismanaged.

2.13 Clean-Architecture

Figure 13. Logo of Clean-Architecture

a. Introduction to Clean Architecture

Clean Architecture is a software design philosophy introduced by Robert C. Martin (Uncle Bob) that organizes code into independent layers with a strict dependency rule. In modern applications, it is used to separate business logic (Entities and Use Cases) from external concerns like frameworks, UI, and databases. It plays a role similar to Hexagonal Architecture (Ports and Adapters) or Onion Architecture in creating maintainable and scalable systems.

b. Advantages of Clean Architecture

  • Framework Independence: The core logic does not depend on specific libraries or tools, making it easy to swap frameworks (e.g., changing from ASP.NET Core to another technology).
  • Highly Testable: Business rules can be tested in isolation without requiring a database, UI, or web server.
  • Database Independence: You can swap the data storage layer (e.g., moving from SQL Server to PostgreSQL) without touching the core business logic.
  • Maintainability: Changes in external layers (UI or API) do not affect the internal business rules, reducing the risk of side effects.
  • Scalability: Clear boundaries make it easier for large teams to work on different parts of the system simultaneously.

c. Disadvantages of Clean Architecture

  • Increased Complexity: Introduces many layers and abstractions, which can be overkill for small or simple projects.
  • Boilerplate Code: Requires writing more code (interfaces, mappers, and data transfer objects) to maintain separation between layers.
  • Steep Learning Curve: Developers need a solid understanding of design patterns and dependency injection to implement it correctly.
  • Performance Overhead: The constant mapping between different layer models (e.g., converting an Entity to a DTO) can slightly impact performance.

2.14 JavaScript

Figure 14. Logo of JavaScript

a. Introduction to JavaScript

JavaScript (JS) is a lightweight, interpreted, or just-in-time compiled programming language with first-class functions, primarily known as the scripting language for Web pages. In modern development, JavaScript is used across the entire stack: for frontend interactivity (React, Vue), backend logic (Node.js), and mobile app development (React Native). It plays a role similar to Python for versatility or Java/C# when used in enterprise backend environments via Node.js.

b. Advantages of JavaScript

  • Universal Reach: The only language that runs natively in all modern web browsers without requiring plugins.
  • Event-Driven & Asynchronous: Non-blocking I/O via the Event Loop makes it highly efficient for handling concurrent operations.
  • Massive Ecosystem: Boasts the world's largest package registry (npm), providing millions of pre-built libraries for any task.
  • Full-Stack Capability: Allows developers to use a single language for both client-side and server-side development.
  • Low Barrier to Entry: Easy to start with a simple text editor and browser, with a flexible syntax that encourages rapid prototyping.

c. Disadvantages of JavaScript

  • Single-Threaded Nature: Can struggle with CPU-intensive tasks (like complex calculations or video encoding) compared to multi-threaded languages.
  • Dynamic Typing Issues: Lack of strict typing can lead to "runtime errors" that are hard to debug (often solved by using TypeScript).
  • Fragmentation: The fast-moving ecosystem (new frameworks every year) can lead to "JavaScript fatigue" and maintenance challenges.
  • Security Risks: Because it runs on the client side, it is susceptible to vulnerabilities like Cross-Site Scripting (XSS) if not handled carefully.

2.15 Python

Figure 15. Logo of Python

a. Introduction to Python

Python is a high-level, interpreted programming language known for its emphasis on code readability and simplicity. In modern development, Python is the leading language for Data Science, Machine Learning, and Artificial Intelligence, while also being widely used for backend web development (Django, Flask) and automation scripting. It plays a role similar to JavaScript in terms of flexibility or R in the context of statistical computing and data analysis.

b. Advantages of Python

  • Simple & Readable: Its syntax mimics natural English, making it exceptionally easy to learn, read, and maintain.
  • Extensive Libraries: Offers a massive ecosystem of libraries like NumPy, Pandas, and TensorFlow, which dominate the AI and data sectors.
  • High Productivity: Allows developers to write fewer lines of code compared to C# or Java to achieve the same functionality.
  • Versatility: A "glue language" that integrates easily with other languages (C/C++) and can be used for web, desktop, and scientific apps.
  • Large Community: One of the world's most popular languages with endless tutorials, documentation, and community support.

c. Disadvantages of Python

  • Execution Speed: Being an interpreted language, it is significantly slower than compiled languages like C++, C#, or Java for heavy computation.
  • Mobile Development: Not a native choice for mobile app development; frameworks like Kivy or BeeWare exist but aren't as mature as React Native or Flutter.
  • Memory Consumption: Python's high-level abstractions and "garbage collection" make it less memory-efficient than lower-level languages.
  • Global Interpreter Lock (GIL): The GIL prevents multiple native threads from executing Python bytecodes at once, limiting true multi-core CPU utilization.

2.16 PyTorch

Figure 16. Logo of PyTorch

a. Introduction to PyTorch

PyTorch is an open-source machine learning framework based on the Torch library, primarily developed by Meta's AI Research lab (FAIR). In the AI ecosystem, it is used for applications such as computer vision, natural language processing (NLP), and deep learning research, providing a flexible "tensor" library with GPU acceleration. It plays a role similar to TensorFlow or JAX in the field of deep learning and neural network development.

b. Advantages of PyTorch

  • Dynamic Computational Graph: Uses "Define-by-Run" logic, allowing developers to change network behavior on the fly, which is essential for debugging and research.
  • Pythonic Nature: Deeply integrates with the Python ecosystem (NumPy, SciPy), making it feel natural and intuitive for Python developers.
  • Strong Research Adoption: The preferred framework for the majority of academic AI papers due to its flexibility and ease of prototyping.
  • Excellent Documentation: Offers clear, comprehensive guides and a massive community that shares pre-trained models via PyTorch Hub.
  • Distributed Training: Provides native support for asynchronous execution and distributed training across multiple GPUs and nodes.

c. Disadvantages of PyTorch

  • Deployment Complexity: Traditionally perceived as more difficult to deploy to production or mobile devices compared to TensorFlow (though TorchServe and LibTorch have improved this).
  • Minimal High-Level API: While libraries like PyTorch Lightning help, the core API is relatively low-level, requiring more code to build standard models.
  • Fragmented Ecosystem: Unlike TensorFlow's all-in-one suite (TFX), PyTorch relies on a collection of separate libraries for monitoring and deployment.
  • Performance on CPU: While excellent on GPUs, it may require additional optimization (like OpenVINO) to achieve peak performance on standard CPU hardware.

2.17 FastAPI

Figure 17. Logo of FastAPI

a. Introduction to FastAPI  

FastAPI is a modern, high-performance web framework for building APIs with Python, based on standard Python type hints. In backend development, it is used to create robust, production-ready RESTful or GraphQL APIs, leveraging Pydantic for data validation and Starlette for web capabilities. It plays a role similar to Flask or Django Ninja in Python, or Go Gin and Node.js (NestJS) in terms of performance and developer experience.

b. Advantages of FastAPI  

  • High Performance: One of the fastest Python frameworks available, with performance on par with Node.js and Go, thanks to its asynchronous core (async/await).
  • Fast Development: Features like automatic interactive documentation (Swagger UI and ReDoc) and type safety significantly speed up the coding process.
  • Data Validation: Built-in integration with Pydantic ensures that incoming data is automatically validated and converted to the correct Python types.
  • Reduced Bugs: Heavy use of type hints allows editors to provide better auto-completion and catch errors before the code even runs.
  • Modern Standards: Fully supports and encourages modern standards like JSON Schema, OAuth2, and OpenID Connect.

c. Disadvantages of FastAPI

  • Deployment Complexity: Traditionally perceived as more difficult to deploy to production or mobile devices compared to TensorFlow (though TorchServe and LibTorch have improved this).
  • Minimal High-Level API: While libraries like PyTorch Lightning help, the core API is relatively low-level, requiring more code to build standard models.
  • Fragmented Ecosystem: Unlike TensorFlow's all-in-one suite (TFX), PyTorch relies on a collection of separate libraries for monitoring and deployment.
  • Performance on CPU: While excellent on GPUs, it may require additional optimization (like OpenVINO) to achieve peak performance on standard CPU hardware.

4. Business Opportunity

The rapid growth of digital transformation, remote work, and lifelong learning has significantly increased the demand for online education platforms. Individuals, students, and working professionals are increasingly seeking flexible and affordable ways to acquire new knowledge and skills without being limited by location or time. At the same time, many instructors, experts, and small training organizations are looking for effective channels to commercialize their educational content and reach a wider audience.

The current online learning market is dominated by large platforms such as Udemy, which provide massive course libraries but are highly competitive and limit instructors’ control over branding, pricing strategies, and users relationships. On the other hand, smaller platforms such as Coursmos focus mainly on micro-learning and content sharing, but lack comprehensive marketplace functions, professional learning management features, and strong monetization support. As a result, there remains a clear market gap for a platform that combines the openness of a marketplace with a complete, flexible, and instructor-friendly system.

The Online Course Marketplace System (OCMS) is proposed to address this opportunity by providing a centralized, scalable platform where multiple instructors can easily create, manage, and sell online courses, while users can conveniently discover, purchase, and study courses in one integrated environment. OCMS will support core business functions such as multi-vendor management, secure payments, course content delivery (video and documents), learning progress tracking, and course evaluation.

OCMS targets independent instructors, training centers, and content creators who need a professional yet accessible system to distribute and monetize courses, as well as students and working professionals who seek reliable, structured, and diverse online learning resources. By solving the problems of fragmented content distribution, limited control for instructors, weak learning management on small platforms, and the overcrowded nature of major marketplaces, OCMS fits well with current market trends toward personalized learning, creator-driven education, and digital skill development.

5. Software Product Vision

For instructors, training organizations, and independent knowledge creators who want to publish, manage, and sell online courses, the Online Course Marketplace System (OCMS) is a web-based learning marketplace platform that enables course creation, secure transactions, and integrated online learning through a single centralized system. OCMS allows users to easily discover, purchase, and access high-quality courses that include video lectures and digital learning materials, anytime and anywhere.

Unlike fragmented small-scale course websites or overcrowded large marketplaces, OCMS provides a balanced ecosystem that supports both content creators and users. Instructors are empowered with flexible tools to manage their courses, pricing, and users, while students benefit from a structured learning environment with progress tracking, course evaluations, and reliable content delivery.

When fully implemented, OCMS will create an open yet controlled digital learning environment where knowledge can be efficiently commercialized, skills can be continuously developed, and high-quality education becomes more accessible. The system is designed to be scalable, secure, and sustainable, aligning with current e-learning market trends while remaining realistic in terms of development cost, technical architecture, and operational resources.

6. Project Scope & Limitations

The Online Course Marketplace System (OCMS) is scoped as a web-based platform designed to support a multi-vendor online course marketplace, where instructors can create, manage, and sell courses, and users can browse, purchase, and study courses within a centralized system. The project focuses on building the essential marketplace and learning management capabilities required to operate a functional and scalable online education platform.

Within this scope, OCMS will provide core features including user registration and authentication for different roles (administrator, instructor, and user), course creation and management tools for uploading video lectures and digital learning materials, and marketplace functions such as course browsing, searching, filtering, and categorization. The system will support secure payment processing, enrollment management, and access control to purchased courses. Users will be able to stream course videos, download learning materials, track their learning progress, and submit course ratings and reviews. Administrative functions will include user management, course moderation, and system monitoring to ensure platform stability and content quality.

At the same time, the project scope is intentionally limited to ensure feasibility within available time, budget, and technical resources. The initial version of OCMS will not include:

  • The initial version of the OCMS system does not include native mobile applications.
  • Live classes or real-time video conferencing are not supported.
  • Advanced artificial intelligence-driven learning features are excluded.
  • Official certification or degree-granting capabilities are not included.
  • Offline protected video access is not supported.
  • Deep integration with external enterprise systems is excluded.
  • Large-scale marketing operations and instructor recruitment services are also outside the scope of this project.

Any proposed requirements that fall outside these boundaries will be considered out of scope and will only be addressed if they provide significant value and are accompanied by justified changes to project schedule, cost, and resource allocation.

6.1 Major Features

FE-01: User & Authentication Management: Supports registration, email verification, multi-method login (Google), and profile management for Users, Instructors, Staff, and Admin. Manage instructor applications.

FE-02: Course Discovery & Information Management: Provides search, filter, and sort capabilities for courses, as well as detailed syllabus and instructor profile views for Guests/Users.

FE-03: Content & Learning Management: Manages course enrollment, access to learning materials, and personal study progress tracking for Users

FE-04: Instructor Content & Course Management: Enables Instructors to create and edit courses/lessons, toggle course visibility, and manage their taught course list.

FE-05: Cart & Purchase Management: Manages shopping carts, wishlists, secure payments via Stripe, coupon applications, and gifting courses to other users.

FE-06: Communication & Interaction Management: Handles system notifications, direct messaging, and interactive chats between users, support staff, and instructors.

FE-07: Course Review & AI Moderation Management: Manages the course rating and review system, integrating AI services to automatically moderate lesson content and course reviews.

FE-08: Content Moderation & Quality Management: Provides tools for Staff to approve course publications or updates, manage violating reviews, and flag users for non-compliance.

FE-09: Financial & Payout Management: Manages balances, transaction histories for system and instructors. Additionally, manage transfer rates, automated payout schedules for instructors, and fund withdrawals for the system.

FE-10: User Reporting & Complaint Management: Handles user-submitted reports on violating courses or reviews, complete with status tracking and staff responses.

FE-11: System Operation & Coupon Management: Provides comprehensive user list management (CRUD) for administrators and controls the lifecycle of promotional coupons.

FE-12: AI Service & Activity Management: Manages AI service configurations, detects confidence thresholds, and tracks system activity logs for auditability.

6.2 Limitations & Exclusions

LI-01: Offline Learning Capability: The system requires a constant internet connection to stream videos and access materials. Offline viewing or downloading content for local use is not supported.

LI-02: Advanced Accounting and Taxation: While the system tracks balances and payouts, it does not provide complex accounting tools, personal tax calculation for instructors, or integration with local banks outside of the Stripe API.

LI-03: Integrated Professional Video Editing: Instructors must prepare and edit their videos using external software before uploading; the platform does not provide built-in professional video editing or post-production tools.

LI-04: Real-time Virtual Classrooms: The platform is designed for on-demand video learning; live streaming, real-time video conferencing (e.g., Zoom/Meet integration), and live webinars are excluded from the current scope.

LI-05: Academic Content Accuracy: The system provides tools for reporting violations, but the platform owner is not responsible for the professional accuracy or subjective quality of the knowledge shared by independent instructors.

LI-06: Technical Proficiency Requirement: The administrative and course management interfaces assume a baseline level of technical literacy; the system is not fully optimized for users with zero experience in digital software operations.

LI-07: Manual and Cryptocurrency Payments: Financial transactions are restricted to methods supported by the Stripe API; the system does not support manual bank transfers, or any form of cryptocurrency.
