2. Installation Guides

2.1 System Requirements

       ● For service project (Backend API & Database):

○ Operating system: Windows 10 (version 2004 or higher) / Windows 11 (WSL2 enabled for Docker).

○ Storage: SSD 256GB or higher.

○ RAM: 8GB or higher (16GB recommended for running Docker and Visual Studio smoothly).

○ CPU: Intel Core i5 10th generation or higher.

○ Database & Cache: PostgreSQL 15+ (with pgvector extension) and Redis.

       ● For web client (Frontend MVC):

○ Operating system: Windows 10 or higher.

○ Browser: Google Chrome, Edge, CocCoc, etc.

2.2 Setup Files

● Docker Desktop for Windows Installer (Required to run PostgreSQL, pgvector, and Redis via Docker Compose).

● pgAdmin 4 or DBeaver Setup (Optional - For PostgreSQL database management).

● dotnet-sdk-8.0-win-x64.exe (or ASP.NET Core Runtime 8.0 Hosting Bundle if deploying).

● Visual Studio 2022 Installer (Ensure "ASP.NET and web development" workload is selected).

2.3.4 Install pgAdmin

Step 1: Download pgAdmin

The official website of pgAdmin offers an executable file to install PostgreSQL's GUI interface app easily. Hence, visit it using the given link and download the same on your Windows 11 or 10 system. You will have the list of the supported versions; select the latest one, and download the same.

Step 2: Run the Setup

Once you have the setup on your system, double-click on it to run the same, and click on Install for me only (recommended); however, if you want to install pgAdmin for all users’ accounts on your system, then you can for the second option.


Figure: Installing pgAdmin

 Step 3: Install pgAdmin on Windows 11 or 10

Start the installation by clicking the Next button and then Accepting the license. After that, again click the Next buttons to accept the default setting until the setup starts the installation process. Soon, the installation will be completed; confirm it by pressing “Finish.”

 

 

Step 4: Launch the pgAdmin

To start the application or GUI interface app for PostgreSQL Database, go to your Windows search and type pgAdmin; as its icon appears, click to run the same. 

 

After the start, you will be asked to assign a master password. Remember this is used to store the sensitive connection data to your databases in encrypted form. The master password is not stored anywhere, so you must remember it well.

Step 5: Connect pgAdmin to Remote PostgreSQL Server

To establish a connection with your remote PostgreSQL Database, click on Add New Server.

In this dialog box, you enter a name for your server to identify it later quickly. It can be the actual name of the remote server or whatever you want to call it on pgAdmin.

Here we are going for a TCP connection, and for that, click on the Connection Tab. After that, you have two options: Configure a direct link to the server via TCP or an indirect reference to the server via SSH tunnel. You can choose the one you want.

Now, in the Connection tab, enter the Ip-address or domain name of the server on which your PostgreSQL instance is installed.

Leave the Port and Maintenance Database values as they are, and add the PostgreSQL instance Database Username and Password you want to access on pgAdmin.

Next, click on the Save button to let the program establish a connection.

Finally, you will have the graphical user interface with PostgreSQL Database to create, delete and edit tables, including other tasks such as backup and restore.

3.2 Authentication

3.2.1 Register

The purpose of this workflow is to allow the Guest to register a new account on the system.

Execution steps:

Step 1: The Guest accesses the registration page by pressing thebutton on navigation bar.

 

Step 2: The Guest inputs information:

  • Full Name: The full name of the Guest. This field is required.
  • Email Address: The email address of the Guest. This must be a valid Gmail address and is required.
  • Username: A unique username for the account. This field is required.
  • Password: A secure password for the account. This field is required.
  • Confirm Password: A confirmation of the entered password. This must match the password field and is required.

 

Step 3: The Guest clicks the   button to register a new account.

3.2.2 Login

The purpose of this workflow is to allow the User/Instructor/Staff/Admin to log into an existing account on the system.

Execution steps:

Step 1:  The User/Instructor/Staff/Admin accesses the login page by pressing the  button on navigation bar.

 

Step 2: The User/Instructor/Staff/Admin inputs information:

  • Username or Email: The registered username or email address associated with the account.
  • Password: The password for the account.

 

Step 3: The User/Instructor/Staff/Admin  clicks the  button.

3.2.3 Login with Google

The purpose of this workflow is to allow the User/Instructor to log into the system or create a new account using their Google credentials.

Execution steps:

Step 1: The User/Instructor accesses the login page by pressing the  button on navigation bar.

 

Step 2: The User/Instructor clicks the  button to open the Google authentication modal.

 

Step 3: The User/Instructor authenticates with their Google account.

 

3.2.4 Verify Email

The purpose of this workflow is to allow the User to verify their email address using a One-Time Password (OTP).

Execution steps:

Step 1: The User accesses My Profile page then accesses Verify OTP page by pressing the  button.

 

Step 2: The User inputs information:

  • Enter OTP Code: The 6-digit OTP code received in the email. This field is required.

 

Step 3: The User clicks the  button to finish email verification.

3.2.5 Change Password

The purpose of this workflow is to allow the User to update their account password for security purposes.

Execution steps:

Step 1: The User accesses the Change Password page by pressing button in the sidebar of My Profile page.

 

Step 2: The User inputs information:

  • Current Password: The current password of the account. This field is required.
  • New Password: The new password to be set. This field is required and must be at least 6 characters.
  • Confirm New Password: The confirmation of the new password. This field is required and must exactly match the new password.

 

Step 3: The User clicks the button to finish changing password.

3.2.6 Forget Password

The purpose of this workflow is to allow the User/Instructor to reset their account password if they have forgotten it.

Execution steps:

Step 1: The User/Instructor accesses the Forgot Password page by pressing the  button in the login page.

 

Step 2: The User/Instructor inputs information:

  • Email Address: The verified email address associated with the account. This field is required.

  

Step 3: The User/Instructor clicks the  button to receive the verification code and navigate to the Verify OTP page.

Step 4: The User/Instructor inputs information:

  • Enter OTP Code: The 6-digit OTP code received in the email. This field is required.

  

Step 5: The User/Instructor clicks the  button to navigate to the Reset Password page.

Step 6: The User/Instructor inputs information:

  • New Password: The new password for the account. This field is required.
  • Confirm Password: The confirmation of the new password. This field is required and must exactly match the new password.

 

Step 7: The User/Instructor clicks the  button to finish reset password.

3.2.7 Logout

The purpose of this workflow is to allow the User/Instructor/Staff/Admin  to log out of their account securely.

Execution steps:

Step 1: The User/Instructor/Staff/Admin accesses the user menu from the system navigation.

 

Step 2:  The User/Instructor/Staff/Admin clicks the button, the system will log out and redirect to the homepage.

3.4 Course Moderation

3.4.1 View Course Moderation List

The purpose of this workflow is to allow Staff, Admin to display all courses submitted by instructors that are pending moderation review.

Execution steps:

Step 1: The Staff or Admin accesses the Course Moderation List page using one of the following entry methods:

  • Option 1.1 (Sidebar Navigation): Click the Course Moderation menu item on the left sidebar of the Admin Dashboard.
  • Option 1.2 (Real-time AI Moderation Notification): Click the View Detail link on the real-time AI moderation notification banner ("Manual Review Required") that automatically pops up in the top-right corner of any Admin/Staff Dashboard page whenever a course is submitted and evaluated by the AI moderation engine.

 

 

Step 2: The Staff or Admin inspects the course moderation queue:

  • Course Thumbnail & Title: View course thumbnail image, title, and category.
  • Instructor Information: Name and email address of the instructor who authored the course.
  • Submission Date: Date and time timestamp when the course was submitted for review.
  • AI Moderation Score: Automated AI safety compliance score and flagged content indicators.
  • Moderation Status: Status badge indicating Pending Review, Approved, Rejected, or Flagged.

 

Step 3: The Staff or Admin clicks on the View Details icon () on a course submission entry to open its moderation details.

 

3.4.2 Search Courses

The purpose of this workflow is to allow Staff, Admin to search the course moderation queue by title, keywords, or instructor name in real-time.

Execution steps:

Step 1: At the Course Moderation List page, the Staff or Admin locates the search control bar.

 

Step 2: The Staff or Admin enters search keywords into the Search Input field.

 

Step 3: The system automatically filters and displays matching course moderation entries in real-time.

 

3.4.3 Sort Courses

The purpose of this workflow is to allow Staff, Admin to sort courses in the moderation list by submission date or risk level.

Execution steps:

Step 1: At the Course Moderation List page, the Staff or Admin locates the sorting header control.

 

Step 2: The Staff or Admin clicks the Sort By dropdown menu and selects a sorting criteria:

  • Submission Date (Oldest First): Prioritize older pending course submissions.
  • Submission Date (Newest First): Display the most recently submitted courses first.
  • Risk Score (Highest First): Sort by AI violation risk score descending.

 

Step 3: The Staff or Admin clicks the selected option to reorder the course queue.

 

3.4.4 Filter Courses

The purpose of this workflow is to allow Staff, Admin to filter courses by categories or moderation status (Pending, Approved, Rejected, Flagged).

Execution steps:

Step 1: At the Course Moderation List page, the Staff or Admin locates the filter dropdown controls.

 

Step 2: The Staff or Admin clicks the Status Filter Dropdown or Category Dropdown to view available filter options:

  • Status Filter Dropdown: Select Pending Review, Approved, Rejected, or Flagged.
  • Category Dropdown: Choose a specific course category to narrow down results.

 

 

Step 3: The Staff or Admin clicks the selected filter option to update the course list.

Step 3: The Staff or Admin clicks the  button to return the course draft to the instructor.

3.5 Instructor Application

3.5.1 Become An Instructor

The purpose of this workflow is to allow a registered learner to submit an instructor application by providing professional credentials, teaching expertise, and identity verification documents to join the platform's instructor team.

Execution steps:

Step 1: The registered learner accesses the marketplace and clicks the navigation link in the top navigation bar.
 

Step 2:The registered learner reviews the Instructor Application Form and inputs information / selects actions: 

  • Professional Title: Required. Enter a professional headline or teaching title (e.g., Senior Solution Architect & Cloud Developer).
  • Areas of Expertise: Required. Enter technical domains, programming languages, or topics specialized in teaching (e.g., C#, .NET Core, Cloud Computing).
  • LinkedIn Profile: Optional. Enter a valid URL linking to a professional LinkedIn profile account.
  • Stripe Payout Country: Required. Select the target billing and payout country from the dropdown selection list (e.g., United States).
  • YouTube Channel: Optional. Enter a valid URL linking to a YouTube teaching or demo video channel.
  • Facebook Profile: Optional. Enter a valid URL linking to a professional Facebook social media page or profile.
  • Biography & Professional Experience: Required. Enter a comprehensive summary detailing teaching experience, industry background, and educational qualifications (minimum 50 characters required).
  • Verification Documents (Max 3): Required for initial submissions. Upload up to 3 valid identification or professional credential files (.pdf, .jpg, .jpeg, or .png format, maximum size of 5MB per file) into the designated document slots. When resubmitting an application, any previously stored documents are retained and displayed as removable preview cards.
     

Step 3: The registered learner clicks the button (or the Resubmit Application button if updating a previously rejected submission).


Step 4: The system successfully submits the application and redirects the registered learner to the Instructor Dashboard page. This dashboard displays the submitted Application Details and indicates that the Application Status is Pending admin review.


3.5.2 View Instructor Applications

The purpose of this workflow is to allow Staff and Admin members to view and browse the list of pending instructor registration requests, inspect applicant profile summaries, and access processing actions.

Execution steps:

Step 1: The staff/admin accesses the Dashboard and clicks the Instructor Approvals menu item to open the Instructor Registration Requests page.

 

Step 2: The staff/admin inspects the summary statistics cards at the top of the page to review total pending approvals, profiles with LinkedIn, and submitted resumes.

    

Step 3: The staff/admin inspects the registration requests list in the data table and selects actions:

  • Instructor: Displays the applicant's avatar image, full name, and registered email address.
  • Specialization: Displays the applicant's professional title and category tags representing their teaching expertise areas.
  • LinkedIn: Displays a clickable link ("LinkedIn") to open and verify the applicant's external LinkedIn profile in a new browser tab, or displays "Not Provided" if unsubmitted.
  • Portfolio / Resume: Displays clickable document buttons for uploaded resume or portfolio files (e.g., Document #1 (.pdf)). The staff/admin can click any document button to open and review the submitted file in a new browser tab.
  • Actions: Displays processing controls for each application row, including the View Info link to inspect full application details, the Approve button to accept the registration request, and the Reject button to decline the request.

Step 4: The staff/admin clicks a  button in the pagination controls to view additional pending applications.

Execution steps:

The staff/admin can click "Visit Profile" or "Visit Channel" to open the external profile in a new browser tab, or view "Not Provided" if the link was unsubmitted.
  • Submitted Documents: Displays clickable links for uploaded resume or portfolio files (e.g., Document #1 (.pdf)). The staff/admin can click any document link to open and review the submitted file in a new browser tab.

 

Step 3: The staff/admin clicks the  button.

3.5.4 Approve Instructor Application

The purpose of this workflow is to allow Staff and Admin members to approve a pending instructor registration application, upgrading the user's role to Instructor and publishing their status.

Step 2: The staff/admin inputs information / selects actions:

  • Reason for Rejection: Required. Enter a detailed explanation specifying why the instructor application is being declined (e.g., insufficient credentials or missing portfolio documents). Leaving this field blank will trigger a validation error ("You must enter a reason for rejection!").

Step 3: The staff/admin clicks the button on the modal dialog.
